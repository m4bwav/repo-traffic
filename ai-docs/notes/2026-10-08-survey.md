# Phase 0 survey (2026-10-08)

## Summary

A 253-line stdlib script with no tests, CI or releases; the golden capture confirms eight rough edges, the worst being that one failing npm or NuGet call fails the whole run before daily.csv is merged.

The first package-modernize run on a Python tool. The reference is the frozen source of commit `9b6e754` (nothing was ever published), recorded by `tests/golden/` (see [../../tests/golden/README.md](../../tests/golden/README.md)). Raw GitHub survey output: [2026-10-08-survey-github.txt](2026-10-08-survey-github.txt).

## What it is

`repo_traffic.py`, 253 lines, standard library plus the `gh` CLI. One run fetches, for every repository the owner has: daily views and clones (`traffic/*?per=day`), referrers, popular paths, stars, forks, release asset downloads; npm downloads for the packages a `maintainer:` search finds (14 daily counts and last month); NuGet downloads for the packages an `owner:` search finds on both search replicas (highest total wins), plus the undocumented 6-week stats report per package (by version and by client). `install-task.ps1` (22 lines) registers a Windows scheduled task every 13 days.

## Who could use it

Anyone who owns GitHub repositories and wants their traffic kept past GitHub's 14 days, and anyone publishing to npm or NuGet who wants download history in one place. Nothing in the code is specific to one account: the accounts come from flags or `repo_traffic.json`.

## What a stranger needs

- Python 3.9 or later (the README's claim; the capture replays identically on 3.9.25, 3.12.14 and 3.14.6 on Windows, and 3.14.4 on Linux).
- The GitHub CLI, logged in with an account that has push access (traffic is refused otherwise).
- macOS and Linux: `python3` (the README's cron line uses it); `install-task.ps1` is Windows only (the ScheduledTasks cmdlets do not exist in PowerShell on macOS or Linux); the README gives a cron line for the 1st and 15th, nothing for launchd or systemd. `pythonw` and `CREATE_NO_WINDOW` are Windows-only and guarded.

## Every place it reads and writes

| What | Where | How |
|---|---|---|
| Settings | `repo_traffic.json` next to the script | read, flags win |
| Snapshots | `<data>/snapshots/YYYY-MM-DD/github.json`, `packages.json`, `summary.md` | written (text mode: CRLF on Windows, LF elsewhere) |
| Daily traffic | `<data>/daily.csv` | read, merged, rewritten whole (always CRLF: csv module) |
| Downloads | `<data>/downloads.csv` | appended; header written only when the file is new |
| Run log | `<data>/run.log` | appended, one line per run, ok or FAILED |
| Summary | stdout | the same tables as `summary.md` |
| Network | `gh` (api.github.com), registry.npmjs.org, api.npmjs.org, azuresearch-usnc and -ussc.nuget.org, www.nuget.org | read only |
| Scheduler | Windows Task Scheduler (`install-task.ps1`) | one task, `pythonw` with the clone as working directory |

`<data>` is `data` next to the script unless `--data` or the config says otherwise (relative paths resolve against the script's folder). Both `data/` and `repo_traffic.json` are gitignored.

## Confirmed by the golden capture (18 cases, Windows and Linux)

1. A repository without push access is silent: `gh` exits 1 with HTTP 403, the script stores `null` and the summary shows 0 (`no-push-access`).
2. One failing source fails the whole run after `github.json` is written and before `daily.csv` is merged: an empty npm body (`npm-empty-body`, JSONDecodeError), npm 429 five times (`npm-429-every-time`, after sleeps of 10, 20, 30 and 40 s), one NuGet replica answering 503 (`nuget-replica-503`) or refusing connections (`nuget-replica-unreachable`, four 5 s retries), an npm search 404 (`npm-search-404`, TypeError).
3. `--help` runs a full snapshot (`help-flag-runs-a-snapshot`); `--top` with no value raises IndexError (`top-without-value`); unknown flags are ignored.
4. A failure before the data folder is known logs to `data/` next to the script, not to the `--data` folder (`gh-login-fails-logs-to-default-data`).
5. An existing `downloads.csv` with the older six-column header gets seven-column rows appended under it, silently (`downloads-csv-old-header`).
6. Ties in the summary keep the API's order: npm and release tables sort by one count only, the GitHub tables by two (`full`: alpha-lib and gamma-cli both 20 in 14 days).
7. The only difference between Windows and Linux is line endings (snapshots, summary, run.log and stdout CRLF on Windows; the CSVs CRLF everywhere).
8. Releases are read with `per_page=100` and no pagination; npm search takes 250 results; `gh repo list` 1,000 (read, not captured).
